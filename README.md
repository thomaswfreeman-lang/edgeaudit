# EdgeAudit

A statistical trade audit. It takes a raw broker export and answers one
question honestly: **is there an edge here, or is this the record a coin flip
would have produced?**

Every other journal on the market is built to find you an edge. This one is
built to find out whether you have one — and to say "not yet, come back in
340 trades" when that is the true answer.

## What makes the answer defensible

| Problem in every other journal | What this does |
|---|---|
| Reports point estimates ("your CL setup: +0.42R") | Reports intervals. Nothing is claimed without one. |
| Treats trades as independent | Stationary block bootstrap — streaks and tilt-clusters don't shrink the interval |
| Tests a slice against zero | Tests it against zero **and** against your own overall average, by label permutation. A slice that only beats zero is inheriting your global edge, not adding one. |
| Slices 40 ways, shows you the winners | Every tested slice enters one Benjamini–Hochberg family at q=0.10 |
| Reports the extreme slice at face value | Empirical-Bayes shrinkage toward your global mean. When the spread between slices is pure noise, every slice collapses onto the average — the correct answer. |
| Quotes a Sharpe ratio | Probabilistic and Deflated Sharpe (Bailey & López de Prado): adjusted for skew, kurtosis, sample length, and the number of slices searched |
| Never mentions sample size | Minimum track record length, plus the smallest effect this sample could detect at all |

## Intake

No template. Drop in the raw export. Auto-detected today:

- Tradovate (performance export)
- NinjaTrader (trade performance)
- TopstepX / ProjectX
- Rithmic (R\|Trader fills) — FIFO round-trip pairing
- Interactive Brokers (trades)
- TradeStation (trades)
- Anything else — fuzzy column matching, needs a symbol and a P&L column

Adding a broker is one `FormatSpec` entry in `parsers.py`. Nothing else changes.

Open positions at the end of the file are dropped, not counted. Including
them would bias the sample toward winners.

## Use

```bash
python -m edgeaudit.cli trades.csv --subject "Apex 250k - Q1" -o report.html
python -m edgeaudit.cli trades.csv --markdown --json summary.json
```

```python
from edgeaudit import audit, report
res = audit.run("trades.csv")
print(res.verdict, res.n_naive_significant, "look significant,", res.n_survived, "survive")
open("report.html", "w").write(report.to_html(res, subject="Account 4471"))
```

## The demo that sells it

`demo_noise_export.csv` is 500 trades generated by a coin flip with the
expectancy forced to exactly zero. There is no edge in it by construction.
Run any journal against it and watch it name your best setup. This one
reports: 4 of 32 slices look significant, 0 survive.

```bash
python -m edgeaudit.cli demo_noise_export.csv --subject "Randomly generated trades"
```

## Tests

`pytest tests -q` — 16 tests. The important ones assert the product claim:
noise must never produce a verified slice, and a *uniform* edge must be
detected globally while being attributed to no slice at all.

## Limits, stated plainly

- Without per-trade risk in the export, 1R is estimated as the median
  absolute loss. The report says so on its face.
- Session bands assume US futures exchange-local time.
- Dollar conversion for fill-level sources requires `point_values`; without
  it, dollar figures are omitted rather than guessed.
- This describes the sample supplied. It is not a forecast.
